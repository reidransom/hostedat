## Implementation and guidance for subsequent tasks

- Inspected all registered creation routes and their model/runtime consumers: KV (`CreateKVNamespace`), D1 (`CreateD1Database`), Durable Objects (`CreateDurableObjectNamespace`) and storage (`CreateBucket`). These are all persisted named bindings consumed by `workeradapter.BuildEnvFromDB`. ASSETS is platform-provided, not provisioned by a creation endpoint. Cron records and S3 credentials do not create named worker bindings. The worker dependency supports queue/service/custom bindings, but this platform has no provisioning models/routes or production `BuildEnvFromDB` assignments for them; no fictitious endpoints or new queue/service features were added.
- `envschema.ValidateName` remains portable grammar only. New `ValidateRuntimeName` is the separate database-free runtime reservation check. ASSETS, __PROTO__, PROTOTYPE and CONSTRUCTOR are reserved case-insensitively. `Schema.Check` applies it to parsed JSON/YAML and programmatically constructed declarations. KV/D1/CACHE are type labels, not automatically occupied names; actual binding names compare exactly and are site-scoped.
- `environment.CheckEnvironmentNames(tx, siteID, names)` checks runtime reservations plus all four persisted binding tables using bound SQL parameters and metadata only. `Bulk` uses it inside the existing `models.WithSiteTransaction` before writes, covering every supplied name and every candidate declaration name, including unsupplied optional names. Single writes already delegate to Bulk. `ValidateStored` uses it for every declaration name before presence/decryption/type checks; read-only remote validation retains its single read snapshot.
- `environment.CheckBindingCreation(tx, site, name)` checks reservations, other persisted bindings, existing plain/secret environment rows and every established active declaration name. All four actual creation handlers call it inside the same `WithSiteTransaction` callback as their insert. Optional-but-absent active declarations reserve names. The shared database writer-lock protocol closes the reverse creation race across connections/processes. Diagnostics contain fixed constraints, not arbitrary namespace/request values; handlers return safe 400 errors, with preexisting storage duplicate checks retaining 409 responses.
- Other namespace naming grammar remains unchanged: legacy lowercase/hyphen names remain accepted by KV/D1/DO; storage keeps its stricter existing uppercase grammar and bucket policy. Names from another site do not collide, and case-sensitive site names remain distinct. New cross-type binding collisions are rejected rather than permitting one object to shadow another.
- `Service.Load` checks existing environment names against persisted binding metadata on a read snapshot and fails closed for legacy environment/object collisions or runtime reservations, instead of delivering an object over a secret string. Environment classification and decryption behavior are unchanged. No schema-activation functionality or capability advertisement was added.
- Task 09 must reuse `ValidateStored(tx, siteID, schema)` inside coordinated activation/rollback; it now includes declaration collisions even for absent optional names. Task 07 checks established active snapshots, not yet-uploaded artifact activation. Subsequent future provisioning paths must use `CheckBindingCreation` in the same coordinated insert callback and extend the central persisted-binding lookup/runtime loader together.
