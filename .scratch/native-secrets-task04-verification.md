## Persistence and API guidance

- `models.Deployment.EnvDeclaration *string` maps to nullable TEXT `env_declaration`. It stores canonical flat JSON from the shared parser when later activation code supplies it. `nil` is absent; pointer-to-`"{}"` is an explicit empty declaration. Task 04 preserves these distinctly through actual SQLite writes/reads; it does not yet load artifact manifests.
- `models.Site.EnvDeclarationsEnforced bool` maps to non-null `env_declarations_enforced`, default false. Both new fields use `json:"-"`; existing management representations are unchanged. The flag is not enabled by task 04.
- `models.WithSiteTransaction(db, siteID, func(tx *gorm.DB, site *models.Site) error) error` is the single database coordination boundary. Pass a root database handle. Its first statement performs a no-op site-row write, acquiring SQLite's writer lock before establishing a read snapshot. It then reloads the site and invokes the callback. Missing sites fail without calling the callback. All checks and writes inside the callback must use `tx`; return any failure to roll back. No external side effects belong in the callback, and audits remain post-commit best effort. There is no process-local mutex or automatic retry.
- Environment upsert/delete, deployment activation/version allocation, rollback, KV namespace creation, D1 database creation, durable-object namespace creation and storage binding insertion now participate. Rollback's active-version and target-deployment checks are inside the lock, using freshly loaded state. Deploy checks the maximum-version query error instead of ignoring it. S3 work retains the existing outside-transaction creation/compensation pattern; cross-binding collision checks will be added inside these callbacks by task 07.
- SQLite is the only supported configured database driver. The actual glebarez/go-sqlite driver accepts `_pragma=busy_timeout(5000)&_pragma=journal_mode(WAL)`, not the old `_busy_timeout`/`_journal_mode` options. Initialization now supplies the real driver options, preserves an existing query separator, and applies them to every pooled physical connection. Separate pooled connections are checked for both WAL and a 5000ms timeout.
- SQLite's writer lock serializes writers database-wide, not merely per site; unrelated-site writers can wait. Timeout/transaction failures return errors without proceeding uncoordinated. This is intentionally a boring SQLite-specific protocol rather than unsupported row-lock SQL or process-local locking.

## Duplicate handling and maintenance contract for task 05

- `models.CheckWorkerEnvDuplicates(db)` examines grouped metadata only. `InitDB` invokes it before model migration and refuses to start on duplicate `(site_id,name)` rows.
- `models.FindWorkerEnvVar(db, siteID, name)` loads at most two rows and returns `models.ErrDuplicateWorkerEnv` on ambiguity rather than using `First` or choosing an implicit winner. The current upsert uses it inside the coordination transaction. No value is included in the sentinel diagnostic.
- `models.InstallWorkerEnvUniqueness(tx)` rechecks duplicates and installs `idx_worker_env_site_name ON worker_env_vars(site_id,name)`. It is intentionally not an AutoMigrate model tag: task 05 must call it inside offline migration's transaction after explicit operator resolution, while all writers/workers are stopped. The helper does not pick a row, merge values or delete data.
- Operator resolution: stop writers/workers, back up the database, identify duplicate groups using only `id,site_id,name,secret` metadata, explicitly decide which IDs to retain/remove, and resolve in a transaction. Run maintenance only once every group is resolved. Startup diagnostics deliberately do not disclose values. Encrypted-storage startup validation and offline commands remain task 05; no plaintext fallback is introduced here.

## Remaining risks and unrun coverage

- No encryption or declaration enforcement is enabled yet. Secrets are still plaintext at this intermediate task; no database/log marker-absence claim is made. Task 05 must migrate all runtime readers and provide offline tools; task 09 must populate/validate canonical snapshots and enable the flag only during successful activation.
- Unique environment index installation is explicitly reserved to offline maintenance. The tested transaction protocol prevents normal concurrent same-name API writes from producing duplicates even before installation; direct/external writers can still create duplicates until maintenance installs the constraint, and startup refuses them.
- SQLite serializes all writers. The 5-second contention deadline can reject a request; no retry guarantees or distributed non-SQLite database support are claimed.
- Real engine coverage is QuickJS, not V8. No live S3 service was provisioned; the storage binding's database boundary is covered through existing fixture-based handler tests. Full suite and complete integration acceptance remain task 15.
