## API and service contracts for subsequent tasks

- Routes remain under authenticated `/api/v1/sites/:id/worker/env`, with existing owner/admin/superadmin authorization and `Cache-Control: no-store` middleware before authentication. Added `POST /bulk` and `POST /validate`.
- Bulk JSON is `{"entries":[{"name":"TOKEN","value":"...","secret":true}],"schema":{"TOKEN":{"type":"string"}}}`. `schema` is optional flat JSON, parsed through `envschema.Parse`, not direct Go map decoding (so duplicate declaration names/rule fields remain errors and required defaults to true). With a schema, all supplied entries must be declared and resolve to secret classification. Omitted `secret` preserves existing classification; new entries default to plain and therefore need explicit true when schema-backed. Candidate-required names omitted from the merge need not exist yet. Candidate documents are never persisted/activated and cannot weaken active rules.
- Single POST accepts the same optional `schema` beside its existing `name,value,secret`. Explicit values are required for both single/bulk; omission/null is rejected and empty is checked according to applicable rules. Strict bounded JSON decoding rejects unknown fields and trailing documents without returning decoder/request contents.
- Shared bounds in `environment`: `MaxBatchEntries=256`, `MaxValueBytes=1 MiB`, `MaxBatchValueBytes=4 MiB` (sum of unescaped name/value byte lengths), `MaxRequestBytes=8 MiB` encoded JSON. Declaration documents retain the shared 1 MiB bound. The encoded-body bound includes escaping, so it is an independent bound, not a guarantee every aggregate-sized combination fits.
- `Service.Bulk(siteID, []Write, candidate envschema.Schema)` is the sole mutation implementation; existing `Set` delegates to it. It rejects empty/duplicate/oversized batches, prevalidates all names/values and candidate rules, prepares all encrypted rows before SQL environment mutations, then writes all rows under one `models.WithSiteTransaction`. Any encryption, SQL, or active-state validation failure rolls the transaction back. It never repeatedly calls `Set`, prunes omitted names, changes existing IDs, or returns partial results.
- `environment.ActiveSchema(tx, site)` reads the active deployment snapshot with site scoping inside the caller's transaction. Explicit `{}` differs from no schema. Broken/missing snapshots on enforced sites fail closed. Single/bulk resulting state must satisfy all running declared requirements; declared names cannot become plain, including present optional declarations. Required-name deletion is rejected, optional deletion allowed. Undeclared legacy plain bindings and explicit undeclared downgrades remain supported.
- `Service.ValidateStored(tx, siteID, schema)` is a reusable read-only check for task 09 activation: it loads only declared rows, rejects plain classification and duplicates, decrypts/authenticates in memory, and runs the shared full validator. `Service.Validate(siteID, schema)` runs that check in one database read transaction/snapshot without the site writer-lock mutation. Remote validation never changes enforcement/deployment fields.
- Validation JSON is only `{"schema":{...}}`; omission/null fails, `{}` succeeds. Client values/unknown fields fail. Success is `{"valid":true,"names":[...]}` with sorted names; failure exposes only a safe variable/constraint or generic storage error. Optional-but-present declarations must still be secret and valid.
- Bulk returns an array of `{id,site_id,name,secret}` only, even for plain entries. Existing single/list DTOs retain plain values, including empty strings, but omit secret values. Delete still selects metadata only and requires no decryption; the real smoke deleted an optional row with deliberately damaged ciphertext.
- Bulk audits use `worker.env.bulk`, one post-commit best-effort record with JSON `names` and `count`. Single/delete retain post-commit names-only actions. Failed/rolled-back mutations emit no success audit; audit storage failure does not fail an already committed mutation. Validation emits no mutation audit. Existing public API reference and CHANGELOG document exercised behavior.
