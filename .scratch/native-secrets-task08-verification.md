## Implementation and API guidance

- New database-free `internal/artifactpolicy` owns the canonical `EnvManifest` filename and case-insensitive dotenv/reserved-metadata component rules. CLI packaging, server extraction, static dispatch, resolved-file lookup and worker ASSETS share it. Dotenv means exactly `.env` or a `.env.` prefix, in any case, at any path depth; `.environment` is not classified by content or prefix guessing.
- `storage.Manager.ExtractZip` now returns `(*string, error)`. The first result is canonical declaration JSON; nil means absent metadata and a pointer to `"{}"` means an explicit empty declaration. Inspected/migrated every extraction caller, including existing API test fixtures and archive tests. The deploy handler stores this result in the existing internal `Deployment.EnvDeclaration` field. The response model still excludes the snapshot from public JSON. No new compatibility shim or metadata alias exists.
- Preflight validates every original path before wrapper flattening, checks types/per-file bounds, then validates every flattened destination and normalized duplicate/file-directory conflict before any deployment-directory write. Rejects case-insensitive dotenv wrappers/files, traversal components, NUL, absolute/drive/UNC/backslash paths, duplicates, symlinks, unsupported types and size/count violations. A file cannot masquerade as the common wrapper directory. Existing 25 MiB compressed/per-file, 256 MiB aggregate and 20,000-entry limits remain; actual streamed extraction is still bounded and failure removes partial assets.
- Only exact artifact-root `_hostedat.env.json` after supported flattening is accepted. It is parsed with the shared bounded strict JSON declaration parser, canonicalized and returned separately, never written into public assets. Nested metadata, case aliases, metadata directories/wrappers and duplicate/conflicting manifests fail. The 1 MiB declaration bound applies, and parser diagnostics remain value-free. Empty and absent manifests stay distinct.
- `ResolveFile` checks both incoming filename components and each candidate's resolved physical destination, including containment. This protects old deployments with dotenv/metadata or symlink aliases. Static HTTP and ASSETS reject forbidden incoming paths and forbidden rewrite targets before SPA fallback. Ordinary missing paths retain safe SPA behavior. Physical aliases cannot return the forbidden asset; they may receive a safe SPA response instead of the blocked file.
- CLI packaging now excludes mixed-case dotenv files and directory components, retaining all symlink exclusions (even a symlink named `_hostedat.env.json`). Ordinary packaging refuses reserved metadata rather than uploading it as content. Task 14 must integrate intentional schema-aware canonical metadata generation and selected-source exclusion; it should reuse this policy, not silently ignore user-supplied conflicting manifests.
- Task 09 must reuse the returned/persisted snapshot for coordinated deployment/rollback/invocation enforcement. This task intentionally does not set `EnvDeclarationsEnforced`, validate current secrets on activation, enable capability support or implement CLI schema packaging. Intermediate metadata acceptance is not the completed secrets release.
