## Implemented contracts and guidance for subsequent tasks

- `internal/environment.Keys` loads an operator-provisioned JSON file via `LoadKeys(path)`. Required shape: `active` key ID plus `keys` mapping IDs to standard-base64 32-byte random keys. Files must be regular, owned by the process effective user and mode 0600/0400; symlinks, missing files, unsupported fields, duplicate JSON keys, trailing documents, invalid IDs/keys and missing active keys fail safely. No generation, JWT derivation or replacement-key fallback exists.
- `models.WorkerEnvVar` adds internal-only `SecretVersion`, `SecretKeyID`, `SecretNonce`, `Ciphertext`. Version 1 uses standard-library AES-256-GCM, random 12-byte nonces and unambiguous JSON associated data binding exact site/name/version. A secret's live `Value` is always empty after migration/writes; ordinary plaintext bindings remain supported with empty encryption metadata. Authentication failures never become plaintext or missing-secret fallbacks.
- `environment.Service{DB, Keys}` is the shared owner of environment operations. `Set(siteID, Write)` requires `Value *string`; omitted/null fails, explicit empty is accepted. `Secret *bool` distinguishes omission from false; omission preserves existing classification and defaults new entries to plain. An explicit false can downgrade an undeclared secret; active-declaration restrictions belong to task 06. IDs and unrelated names are preserved. Static name grammar and 1 MiB value bound are enforced. Errors are fixed value-free sentinels; HTTP errors remain generic and audits remain post-commit names-only.
- `List` selects metadata and CASE-projected public values, not ciphertext or secret plaintext. `Delete` loads metadata only, scopes by site and ID, and uses `models.WithSiteTransaction`. Both work without keys/decryption, including when stored ciphertext is broken.
- `Load(siteID)` returns fresh plain/secret string maps or an error; duplicates and inconsistent secret/plain row formats fail. It is suitable for task 06 read-only validation. Do not implement bulk by repeatedly calling `Set`: extend this package to validate/write the full batch inside one shared site transaction.
- `BuildEnvFromDB(BuildEnvOptions, siteID, assets)` now returns `(*worker.Env,error)`. Options and HTTP `WorkerDeps` carry `Environment *environment.Service`. Production explicitly injects the same service into management routes, HTTP, and cron. All retained adapter/API tests were migrated to the error-returning contract. Other binding-query errors also propagate instead of silently dropping bindings. HTTP fails before engine execution, cron logs a fixed configuration failure and does not dispatch/update `last_run_at`, and dispatcher factories return errors with generic failed results. Already-running snapshots are not mutated.
- `models.OpenDB` is the maintenance-only connection entry point without normal startup schema/data checks. Normal callers retain `InitDB`. Production GORM logging uses `ParameterizedQueries: true`, including failures; input values are not interpolated into SQL logs.
- Server flags: `--secrets-maintenance migrate --writers-stopped`, or `--secrets-maintenance rotate --old-key-file PATH --writers-stopped`, with `--config PATH`. The acknowledgement is mandatory but cannot stop another process. Operators MUST stop every writer and worker. SQLite's maintenance transaction acquires its writer lock before reads, applies schema additions, refuses duplicate site/name groups, encrypts legacy rows/clears plaintext, reads persisted rows back and authenticates/checks counts, and installs uniqueness atomically. Rotation requires a new active key ID not present in the old key set, rejects legacy plaintext, and verifies every re-encrypted row before commit. No decryption export exists.
- `secrets.key_file` is required by production startup. Startup checks all rows, duplicate groups and installed uniqueness before starting workers, cron or traffic. Fresh installations run offline migrate too; missing database parent directories are initialized. Management list/delete deliberately do not require decryption, while server startup and runtime loading do.
- Existing Configuration Reference, example configuration, API/runtime/architecture docs and CHANGELOG now document provisioning, stopped-process operations, separate key/database backups, explicit duplicate resolution, WAL/free-page/old-backup exposure, compaction and retirement limits, key rotation, restore and coordinated binary/database rollback. No actual keys are included.
